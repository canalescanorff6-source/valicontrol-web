VALICONTROL WEB - CONFIGURAÇÃO RUNSITE

Root Directory:
(deixe vazio se manage.py estiver na raiz do GitHub)

Build Command:
bash build.sh

Start Command:
bash runsite_start.sh

Port:
automática/em branco. O projeto usa $PORT.

Environment Variables principais:
SECRET_KEY=cole_uma_chave_grande_aqui
DEBUG=False
RUNSITE=True
DATABASE_URL=cole_a_url_do_neon_aqui
ASAAS_API_KEY=cole_a_chave_do_asaas_aqui
ALLOWED_HOSTS=valicontrol-web.runsite.app,.runsite.app,localhost,127.0.0.1
CSRF_TRUSTED_ORIGINS=https://valicontrol-web.runsite.app,https://*.runsite.app
SECURE_SSL_REDIRECT=False
SESSION_COOKIE_SECURE=True
CSRF_COOKIE_SECURE=True
WEB_CONCURRENCY=1
GUNICORN_THREADS=2

IMPORTANTE:
- Suba o conteúdo extraído, não o ZIP fechado.
- O arquivo manage.py deve ficar na raiz do repositório.
- A pasta data/ deve subir junto, incluindo dados.xlsx e dados.sqlite3.
- Se o site não abrir, abra primeiro:
  https://valicontrol-web.runsite.app/health/
- Se /health/ não abrir, veja os logs de Deploy/Runtime do RunSite.

Catálogo de códigos:
O arquivo data/dados.sqlite3 já vai pronto para não travar o RunSite no start.
Se ele não estiver no GitHub, o site abre, mas a busca automática por GTIN pode não funcionar.
Para recriar manualmente no terminal do RunSite:
python manage.py indexar_catalogo --force


Cadastro protegido por código:
CADASTRO_AUTORIZACAO_OBRIGATORIA=True
CADASTRO_AUTORIZACAO_EMAIL=seu_email_de_administrador
CADASTRO_AUTORIZACAO_WHATSAPP=55DDDNUMERO
CADASTRO_CODIGO_EXPIRA_MINUTOS=30
BREVO_API_KEY=sua_chave_api_brevo
BREVO_SENDER_EMAIL=email_verificado_na_brevo
BREVO_SENDER_NAME=ValiControl Web
DEFAULT_FROM_EMAIL=ValiControl Web <email_verificado_na_brevo>

Fluxo: o usuário solicita o código, o código chega no e-mail autorizado do administrador, e a conta só é criada quando esse código for informado na tela de cadastro.

TELA_CADASTRO_AUTORIZADO_V3
Depois do redeploy, rode:
python manage.py verificar_cadastro_codigo

A resposta correta deve terminar com:
Cadastro por código está ativo na página renderizada.
